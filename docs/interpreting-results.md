# 结果判读指南

## 一、一句话原则

> **只有拿到"安装确实发生了"的客观证据，才算安装成功。
> 退出码 0、窗口关闭、流程结束，都不算。**

## 二、final_status 全表

| 状态 | 判定条件 | 计入成功？ | 常见误读 |
|---|---|---|---|
| `install_completed` | 至少一条**安装证据**（S1/S2/S3/S4/A2/B1…） | ✅ | — |
| `install_unverified` | 只有**弱证据**（通常仅 A1 退出码 0） | ❌ | ✗ 误当作"装好了" |
| `install_partial` | 正证据与反证据**并存** | ❌ | ✗ 误当作"部分成功可接受" |
| `already_installed` | 装前已存在 | ❌ | 单列 |
| `triggered` | 进程被触发/运行，无安装证据 | ❌ | ✗ 误当作"安装成功" |
| `killed_on_timeout` | 超时被终止 | ❌ | 需结合 idle/startup 超时判断 |
| `failed` | 明确失败 | ❌ | — |
| `skipped` | 未执行 | ❌（排除出分母） | 不是失败，也不是成功 |

## 三、证据 ID 速查

**正向**：S1 卸载项 / S2 落盘 / S3 MSI 退出码 0 / S4 MsiInstaller 11707 / A1 退出码 0（弱）/ A2 完成页 / A3 目录变化 / B1 安装器日志
**反向**：N1 失败码 / N2、N3 其它反证据 / N4 卸载项被移除 / N5 实体减少 / N6 稳定期后消失（回滚）

> 注意 `A1` 单独出现时属于**弱证据**——这正是 `install_unverified` 的来源。

## 四、常见误读与正确读法

| 你会看到的 | 不要理解成 | 正确读法 |
|---|---|---|
| 退出码 = 0 | 安装成功 | 只说明进程正常退出；看 S1/S2/S3 |
| `install_unverified` | 安装成功 | **未验证**，需要更多证据 |
| `triggered` | 安装成功 | 只是被运行/触发 |
| 安装器窗口关闭 | 安装完成 | 很多"假成功"样本就是这样（A29-01 专门测这个） |
| `skipped` 多 | 失败多 | 未执行；应从分母排除 |
| 成功率很高 | 工具很强 | 先看分母、权限、版本、是否排除了 skipped |
| `evidence_conflicts` 为空 | 一定没问题 | 只表示没发现冲突证据 |

## 五、成功率怎么读

看到一个百分比，先问四件事：

1. **分母是什么**？是否排除了 `skipped`？
2. **哪个构建**？修前 / 修后 / 当前分发版不能混。
3. **什么权限**？未提权的结果不能代表管理员场景。
4. **哪些样本**？定向子集（如 8 个样本的复测）不能当全套件结论。

本套件在 [reports/summary.md](../reports/summary.md) 中**逐段列出**这些信息，请按段引用。

## 六、耗时怎么读

- `duration_sec` 是**单次尝试**耗时，样本总耗时是各次尝试之和。
- 超长耗时（如 26118 s）通常是机器休眠等外部因素，**不是**工具性能问题——本套件曾出现一次并已单独记为问题。
- 终止耗时受 `idle_timeout_sec` / `startup_timeout_sec` / `task_timeout_sec` 影响，与配置强相关，**跨配置比较无意义**。

## 七、容器输入的特殊性

传入目录或压缩包时，结果 JSON 会包含**解压出的每个文件**的结果。
统计样本成功率时**必须按完整路径过滤**（`samples\` 前缀），否则会被展开实体灌爆，
`skipped` 可虚高到 2500+ 条。


## 八、环境阻塞（environment_blocked）——与工具缺陷区分

有一类"非工具"结果必须单列，**不能**记成工具失败：

| 现象 | 判据 | 处理 |
|---|---|---|
| 桌面锁屏导致 GUI 失败 | `Get-Process LogonUI` 有输出；日志出现「前台是 Windows 默认锁屏界面」「cannot focus sample window」 | 该样本标 `environment_blocked`，不计入工具失败 |
| 被测 exe 被杀软隔离 | `Get-MpThreatDetection` 有记录；后续样本 console 报「系统无法执行指定的程序」 | 整轮作废，还原 exe 后重跑（ISSUE-36） |
| 机器休眠导致耗时异常 | 单文件耗时出现数小时级突变（ISSUE-28） | 剔除该耗时，状态另判 |

判读顺序：**先确认环境正常，再看安装证据**。环境未确认时，任何"失败率"都不成立。
